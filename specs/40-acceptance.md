## 5. 验收执行流程

1. **门禁**：`npx tsc --noEmit` → `npx vitest run` → `npm run build`，三者全绿。
2. **自动项**：`tests/**` 全绿 ⇒ §2 的 AC-A01 ~ AC-A43 勾选。
3. **浏览器项**：`npm run test:browser`（= 构建 + 无头 Chromium 驱动 `dist/`）⇒ §3 的 24 项勾选。
4. **遗留人工项**：按 §3.1 在 Firefox 中补做 AC-M23 的跨引擎部分。
5. **收尾**：勾选 §4 矩阵中全部状态；在 `30-tasks.md` 的「执行记录」中登记。

> 若某项无法通过：在 `30-tasks.md` 记录为 `[!]` 阻塞项，说明具体失败条件与已尝试的修复，并回到对应规范文档确认是「实现缺陷」还是「规范缺陷」。本轮的实践结果见 §6。

## 6. 缺陷与改进记录（发现于验收阶段）

按章程 G5「规范优先」处理：先判定是**实现缺陷**还是**规范缺陷**，再决定改代码还是改规范。

| ID | 类别 | 现象 | 根因 | 处理 |
| --- | --- | --- | --- | --- |
| D-01 | **实现缺陷** | 踩雷时棋盘上**全部 10 颗地雷**都被打上红色「踩中」高亮，而 FR-12 要求唯一高亮 | 渲染层 `cellState` 用 `status === 'lost'` 判定踩中格，无法区分「玩家踩中的那一颗」与「其余被揭示的地雷」 | 改为比较 `explodedAt` 坐标（ADR-16）。这是用户明确要求的规则，实现偏离，属实现缺陷 |
| D-02 | 测试缺陷 | 浏览器验收中初始状态、标记循环等 4 项失败 | 渲染器每次渲染都会整体替换棋盘节点，而断言持有的是渲染前的元素引用（已脱离文档） | 修正验收脚本：操作后**重新查询** DOM。已把该约束写入 plan §8 |
| D-03 | **规范缺陷** | 覆盖率语句 83.33% 未达 90% 阈值 | `types.ts` 全为 `interface`/`type`，编译后无运行时代码却计入分母，以 0% 拉低整体值 | 判定为**度量口径错误**：新增 ADR-13 明确「只统计编译后产出可执行语句的文件」，并同步修改 `vitest.config.mjs` |
| D-04 | **规范违规（实现侧）** | `board.ts` 255 行、`style.css` 292 行，违反 NFR-07（≤ 250 行） | 实现时未及时拆分文件 | 拆出 `src/core/flood.ts` 与 `src/ui/grid.css`。现最大文件 199 行 |
| D-05 | **规范缺陷** | NFR-04 判定条件「`src/core/**` 中 `Math.random` 检索为空」被自身注释文本触发误报 | 判定条件未排除注释；且未说明如何确认随机性确实来自注入种子 | 重写 NFR-04 判定条件为「注释以外的真实 `Math.random(` 调用数为 0」，并补充「随机性全部来自 `createRng`」 |
| D-06 | 测试夹具缺陷 | AC-A24「首击即胜」的种子（脚本中写死 `2`）并不产生首击即胜 | 该常量凭经验猜测而非搜索得来 | 用一次性搜索脚本在真实构建产物中确认种子 `411`/`1219`/`7201`，改用 `411` |
| D-07 | 测试缺陷 | `tests/flood.test.ts` 中两个用例期望值算错（把邻雷数 2 当成 4、把 1 当成 8） | 手算棋盘邻域时看错了图 | 按真实棋盘重算并修正断言。实现本身自始正确 |
| D-08 | 测试缺陷 | `mark.test.ts` 断言「首击展开后旗帜仍为 2」失败 | 展开波按 FR-05 覆盖了那两面旗并清除标记 —— 实现正确，断言与规范矛盾 | 按 FR-05 真实语义重写用例，改为「被展开则标记清除、未被展开则标记保留」 |
| D-09 | **API 契约缺陷** | `shuffle` 对稀疏数组抛错 | `Array.from` 把数组空洞变成显式 `undefined`，与「索引越界」守卫无法区分 | 判定为真实契约陷阱：把「入参必须不含 `undefined`」写入 JSDoc 契约并保留快速失败；新增用例固定该行为 |
| D-10 | 实现改进 | `rng.ts` 原用 `continue` 跳过 `undefined`，会静默掩盖真实的索引 bug | 为消除 `noUncheckedIndexedAccess` 的类型噪音而写得过于宽松 | 改为显式抛错；配合 D-09 形成明确契约 |

**结论**：D-01 是唯一影响用户可见行为的实现缺陷，其余为测试、规范或度量口径问题。全部已修复并复验。

> **一个值得记录的观察**：本轮 10 项中有 6 项（D-02、D-06、D-07、D-08 及 D-03、D-05 的一半）源头是**测试或规范有误，而实现是对的**。
> 这说明「测试失败必须先判断是实现错还是测试错」应当是硬性流程，而不是默认改实现去迁就断言 —— 否则会把正确的实现改坏。

### 6.1 v1.2 新增缺陷（和弦 / 持久化 / 自定义难度 / 移动端手势）

| ID | 类别 | 现象 | 根因 | 处理 |
| --- | --- | --- | --- | --- |
| D-11 | **规范缺陷（断言过度具体）** | AC-M08 断言「棋盘容器恰好 2 个监听器」失败（实际 9） | v1.2 为触屏长按、和弦分别新增了 `pointerdown/pointermove/pointerup/pointercancel` 与 `dblclick/auxclick/mousedown`，容器监听器自然增多。原断言把「事件委托」这一**意图**钉死成了具体数字 | 把判定条件改写为**意图式**：格子上 0 个监听器，且容器监听器数**不随格子数增长**（初级 81 格 vs 高级 480 格测得相同）。已同步更新 §3 的 AC-M08 判定条件 |
| D-12 | **实现缺陷（交互）** | 触屏「短促单击」在紧随 AC-M36 长按之后时不生效（`AC-M37` 首轮失败） | 长按后用 `Date.now() - lastLongPressAt < 500ms` 抑制合成 click；该时间窗会**误吞**紧随其后的合法点击 —— 真实场景即「长按标旗后立刻点另一格翻开」 | 修法不是调小窗口，而是**在新手势开始时（touch `pointerdown`）清除抑制窗口**。既修掉误吞，又保留对合成 click 的抑制；`lastLongPressAt = 0` 重置 + 代码注释说明 |
| D-13 | **规范违规（实现侧）** | `src/ui/controller.ts` 达 259 行，超过 NFR-07（≤ 250 行） | v1.2 往控制器里塞入了自定义面板的显隐/预填/校验/提交逻辑 | 拆出 `src/ui/custom-panel.ts`（`attachCustomPanel`），控制器降回 214 行；最大文件 234 行（`style.css`） |
| D-14 | **规范缺陷（同 D-05 类）** | NFR-03 判定条件「`src/core/**` 中 grep `document\|window\|HTMLElement` 结果为空」被 `persist.ts` 的**说明性注释**（「本文件不引用 localStorage / document / window」）触发误报 | 与 D-05 同因：判定条件未排除注释。任何在注释里解释「本层禁止 X」的写法都会自我误报 | 判定条件改写为「**注释以外的真实代码引用数为 0**」；同时把 `SAVE_KEY` 从 `core/persist.ts` 移到 `ui/storage.ts`（键名属存储层细节，按 ADR-21 归位） |
| D-15 | **可用性缺陷（用户实测发现）** | 用户直接双击打开源码 `index.html`，得到**完全空白的棋盘**，控制台仅报 `blocked by CORS policy` 与 `net::ERR_FAILED` | 该工具链（Vite + TypeScript）下 `index.html` 引用的是 `/src/main.ts`，且 `file://` 的 origin 为 `null`，CORS 必然阻止 ES 模块与 TS 源码加载。**这不是渲染 bug，而是访问方式问题**；但页面没有任何提示，用户无从判断 | 在 `index.html` 加入**内联经典脚本**（`file://` 下可执行）检测：2s 内 `window.__minesweeper` 未挂载则显示黄色提示面板，说明原因并给出 `npm run dev` / `npm run build && npm run preview` 两条路径。已在 `file://` 下用 CDP 实测源码与 `dist/` 两种产物均能正确显示；并新增回归断言确保**正常启动时该面板保持隐藏**（AC-M01）。README 顶部同步加警告 |

**v1.2 结论**：D-12 是唯一影响用户可见行为的实现缺陷（且是真实场景可复现的误吞），
D-13 是规范违规，D-11 是断言写法问题。三项均已修复并复验，浏览器验收由 29/31 转为 **31/31**。
