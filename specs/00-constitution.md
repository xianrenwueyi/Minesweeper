# 项目章程（Constitution）

- 项目名称：Minesweeper（网页版扫雷）
- 文档版本：v1.1.0
- 状态：已批准（baseline）
- 本文件地位：**最高约束文件**。当 `10-requirements.md`、`20-technical-plan.md`、`30-tasks.md` 与本文件冲突时，以本文件为准；任何偏离都必须以 ADR（架构决策记录）形式写入 `20-technical-plan.md` 的「决策记录」章节。

---

## 1. 项目目标

交付一个**纯前端、零后端、零运行时依赖**的网页版扫雷游戏。玩家打开页面即可在三种经典难度下完整游玩一局扫雷：翻开格子、标记地雷、观察计时与剩余雷数、判定胜负、随时重新开始。

项目同时是 SDD（Specification-Driven Development）的示范：**先规范、后实现**，每一行实现代码都能回溯到一条需求，每一条需求都能回溯到一个验收用例。

## 2. 非目标（本版本明确不做）

| 非目标 | 原因 |
| --- | --- |
| 后端服务、账号、排行榜、联网对战 | 目标是纯前端单机游戏 |
| 键盘方向键导航与无障碍读屏支持 | 用户未要求；仅保留「可聚焦按钮 + aria-label」这一基础可达性 |
| 响应式深度适配（自适应栅格、断点布局） | 移动端仅承诺「手势可用 + 棋盘可滚动」，不做像素级适配 |
| 音效、动画特效、主题换肤 | 非核心玩法 |

> 以上非目标**不是**「暂时忽略的缺陷」，而是本版本刻意裁剪的范围。若需要，应作为新需求进入 `10-requirements.md`，而不是在实现中顺手加上。
>
> **v1.1 转正的四项**（原 v1.0 非目标，现已进入需求）：和弦操作（FR-19）、游戏进度持久化（FR-20）、自定义难度（FR-21）、移动端手势（FR-22）。

## 3. 核心原则（Core Principles）

### C1. 领域逻辑与表现层严格分离

游戏的**全部规则**（布雷、翻开、展开、标记、胜负判定）必须存在于不引用任何 DOM / `window` / `document` 的纯 TypeScript 模块中。表现层只负责「把状态画出来」和「把用户输入翻译成动作」。

- 判定方式：`src/core/**` 下任何文件不得出现 `document`、`window`、`HTMLElement`、`localStorage`。
- 理由：规则的正确性必须能被自动化测试穷举验证，而 DOM 测试既慢又脆。

### C2. 状态不可变（Immutable State）

领域状态更新必须返回**新的**状态对象，不得就地修改传入的 `GameState`。这样测试可以同时断言「新状态正确」和「旧状态未被污染」。

### C3. 确定性（Determinism）

给定相同的配置与相同的随机种子，一局游戏的过程与结果必须完全一致。随机数必须通过可注入的种子发生器获得，禁止在领域层直接调用 `Math.random()`。

- 理由：让「雷区是否合法（首击安全、雷数精确）」这类性质可以用固定种子做回归测试。

### C4. 首击必安全是一等公民

布雷必须**延迟到第一次翻开动作发生时**执行，且第一次翻开永远不踩雷。这条规则影响数据流设计（棋盘初始无雷），不可作为事后补丁。

### C5. 所有需求可追溯

每条功能需求有唯一编号 `FR-xx`，每条非功能需求有 `NFR-xx`，每个验收项有 `AC-xx`，每个任务有 `T-xx`。
`specs/40-acceptance.md` 必须维护 FR → AC → T 的双向追溯矩阵，**不允许出现无验收项的需求，也不允许出现无需求来源的验收项**。

### C6. 零运行时依赖

`dependencies` 必须为空。构建与测试工具（Vite、TypeScript、Vitest）只允许出现在 `devDependencies`。

- 理由：扫雷的全部复杂度都在自绘网格与状态机上，引入框架只会增加抽象层与不确定性。

### C7. 规则可观测（Testability Hooks）

为支撑验收测试，应用需在 `window.__minesweeper` 暴露只读的状态快照与受控的动作接口。该接口是**正式契约**，必须随需求变化同步维护，不得作为临时调试产物删除。

### C8. 显示与规则解耦的视觉编码

每个格子的视觉呈现必须由其状态（是否翻开 / 是否地雷 / 是否标记 / 相邻雷数）唯一决定，渲染函数必须是 `状态 → 视图` 的纯映射，不得在渲染中改变规则状态。

## 4. 技术约束（Technology Constraints）

| 项 | 约束 |
| --- | --- |
| 语言 | TypeScript（`strict: true`，禁止 `any` 逃逸；确需时用 `unknown` + 类型收窄） |
| 构建 | Vite |
| 运行时框架 | 无（vanilla DOM） |
| 测试 | Vitest，领域层需覆盖全部规则分支 |
| 模块格式 | ESM |
| 目标浏览器 | 支持 ES2022 的现代桌面浏览器（Chrome / Edge / Firefox 最新版） |
| 样式 | 单个 CSS 文件，使用 CSS 自定义属性；不引入 CSS 框架 |
| 包管理 | npm |

## 5. 质量门禁（Quality Gates）

任何任务标记为「完成」前必须同时满足：

- **G1 类型门禁**：`npx tsc --noEmit` 零错误、零警告。
- **G2 测试门禁**：`npx vitest run` 全部通过；领域层核心规则（FR-04 ~ FR-13）每条至少有 1 个自动化用例。
- **G3 构建门禁**：`npm run build` 成功产出 `dist/`。
- **G4 追溯门禁**：`specs/40-acceptance.md` 的追溯矩阵中，该任务覆盖的每个 FR 都有已勾选的 AC。
- **G5 规范同步**：实现过程中若发现规范有误或不足，**先改规范、再改代码**，并在 `30-tasks.md` 记录规范变更。

## 6. 术语表（Glossary）

| 术语 | 英文 | 定义 |
| --- | --- | --- |
| 单元格 | Cell | 棋盘上的一个格子，具有「是否地雷 / 是否已翻开 / 标记态」三个属性 |
| 棋盘 | Board | `rows × cols` 的单元格矩阵，附带地雷总数 |
| 雷区布局 | Layout | 地雷在棋盘上的分布，由首击位置与随机种子唯一确定 |
| 首击 | First Reveal | 本局第一次成功的翻开动作，触发布雷 |
| 安全区 | Safe Zone | 首击格及其 8 邻域，布雷时排除 |
| 展开 | Flood Fill | 从翻开格出发，对「相邻雷数为 0」的格子递归翻开其邻域 |
| 相邻雷数 | Adjacent Mine Count | 某格 8 邻域内的地雷数量，取值 0–8 |
| 标记 | Mark | 玩家在未翻开格子上施加的状态：`flag`（旗帜）/ `question`（问号）/ `none`（空） |
| 剩余雷数 | Remaining Mines | `总雷数 − 旗帜数`，可为负 |
| 时钟 | Clock | 本局计时器，单位秒，上限 999 |
| 局 | Game | 一次从开始到胜利或失败的过程 |
| 状态快照 | Snapshot | 供测试读取的只读状态副本 |
| 和弦 | Chord | 对已翻开的数字格触发，当其邻域旗数等于数字时，翻开所有未标记的邻格 |
| 存档 | Save | 持久化到 `localStorage` 的未结束对局快照 |

## 7. 修订流程

1. 需求变更 → 改 `10-requirements.md`，同步更新 `40-acceptance.md` 矩阵。
2. 架构变更 → 改 `20-technical-plan.md`，新增 ADR 条目。
3. 任务变更 → 改 `30-tasks.md`，保持任务 ID 稳定（不复用已删除的 ID）。
4. 版本号按语义化版本递增，并在文件头部记录修订历史。
