# 需求规格说明（Requirements Specification）

- 文档版本：v1.2.0
- 上游依据：`00-constitution.md`
- 下游文档：`20-technical-plan.md`、`30-tasks.md`、`40-acceptance.md`

## 1. 概述

### 1.1 产品定位

一个打开即玩的单机网页版扫雷。无账号、无网络请求、无后端。

### 1.2 目标用户

熟悉经典扫雷规则的普通玩家。默认其**已知晓**游戏规则，因此界面不需要教学引导，但必须让「当前状态」一目了然（剩余雷数、已用时间、游戏是否结束）。

### 1.3 需求编号约定

| 前缀 | 含义 |
| --- | --- |
| `FR-xx` | 功能需求（Functional Requirement） |
| `NFR-xx` | 非功能需求（Non-Functional Requirement） |
| `AC-xx` | 验收项（Acceptance Criterion），见 `40-acceptance.md` |
| `T-xx` | 任务（Task），见 `30-tasks.md` |

### 1.4 难度常量（全局唯一定义）

| 难度 ID | 显示名 | 行（rows） | 列（cols） | 雷数（mines） |
| --- | --- | --- | --- | --- |
| `beginner` | 初级 | 9 | 9 | 10 |
| `intermediate` | 中级 | 16 | 16 | 40 |
| `expert` | 高级 | 16 | 30 | 99 |
| `custom` | 自定义 | 9–24 | 9–30 | 10–668 |

> 约定：`rows` 为纵向格子数，`cols` 为横向格子数。高级难度即「30 列 × 16 行」，与经典 Windows 扫雷一致。
> `custom` 难度的参数由玩家输入，约束见 FR-21：宽 9–30、高 9–24、雷 10–668 且雷数 ≤ (宽−1)×(高−1)。

## 3. 功能需求（FR）

每条需求的格式：**描述 → 前置条件 → 行为 → 后置条件**。

### FR-01 初始棋盘生成

- **描述**：应用加载后，必须立即以默认难度「初级」生成并渲染一局未开始的游戏。
- **前置条件**：无（页面首次加载）。
- **行为**：读取 `beginner` 配置（9×9，10 雷），构造全部格子均「未翻开、无标记、非地雷」的棋盘。
- **后置条件**：
  - 棋盘 DOM 中存在 81 个格子元素。
  - 所有格子显示为未翻开态。
  - 游戏状态为 `ready`。
  - 时钟显示 `000`。
  - 剩余雷数显示 `010`。
- **约束**：初始棋盘**不得**包含任何地雷信息（见 FR-07 延后布雷）。

### FR-02 难度默认值与切换

- **描述**：应用必须提供初级、中级、高级三个难度按钮与一个「自定义」入口，且当前难度按钮为选中态。
- **前置条件**：任意。
- **行为**：点击某预设难度按钮后，按 FR-14 以该难度开启全新一局，并把该按钮置为选中态；点击「自定义」入口则展开自定义参数表单（见 FR-21）。
- **后置条件**：页面中恰好一个难度按钮处于选中态，其 ID 与当前局难度一致（`custom` 时「自定义」按钮选中）。

### FR-03 棋盘渲染

- **描述**：棋盘必须以 `cols` 列 × `rows` 行的 CSS Grid 呈现，格子之间无缝隙。
- **前置条件**：存在一个游戏状态。
- **行为**：将每个格子的状态映射为对应的视觉编码。
- **视觉编码表（唯一真源）**：

| 格子状态 | 视觉 |
| --- | --- |
| 未翻开 + 无标记 | 凸起的空白格 |
| 未翻开 + `flag` | 凸起格 + 🚩 |
| 未翻开 + `question` | 凸起格 + `?` |
| 已翻开 + 非雷 + 相邻雷数 0 | 凹陷空白格 |
| 已翻开 + 非雷 + 相邻雷数 1–8 | 凹陷格 + 数字，并按数字着色（1 蓝 / 2 绿 / 3 红 / 4 深蓝 / 5 褐 / 6 青 / 7 黑 / 8 灰） |
| 已翻开 + 雷（失败时揭示） | 凹陷格 + 💣 |
| 已翻开 + 雷 + 是玩家踩中的那一格 | 凹陷格 + 💣 + 红色背景 |
| 未翻开 + 雷 + 玩家标了 `flag`（失败时揭示） | 凸起格 + 🚩（保持玩家标记，或叠加地雷提示，二选一由实现决定，需在 plan 中固定） |

- **约束**：渲染必须是「状态 → 视图」的纯映射（章程 C8），渲染过程不得修改规则状态。
- **性能**：单次全量重绘必须只读取状态，不得触发递归展开等规则副作用。

### FR-04 左键翻开

- **描述**：对未翻开的格子左键单击，必须尝试翻开该格。
- **前置条件**：格子未翻开；游戏状态为 `ready` 或 `playing`。
- **行为**：
  1. 若为 `ready`（尚未布雷），先执行 FR-07 的布雷。
  2. 若该格是地雷 → 执行 FR-12 失败流程。
  3. 若该格不是地雷 → 将其置为已翻开，并执行 FR-05。
- **后置条件**：游戏状态至少为 `playing`，或变为 `lost`。
- **忽略规则**：对已翻开的格子左键单击必须是**空操作**（不改变任何状态）。

### FR-05 空白区自动展开

- **描述**：翻开一个相邻雷数为 0 的格子时，必须自动翻开其 8 邻域，并对其中相邻雷数同样为 0 的格子继续递归展开。
- **前置条件**：刚翻开了一个非雷格子。
- **行为**：以广度或深度优先遍历，把连通的所有「相邻雷数为 0」的格子及其**边界层**（相邻雷数 > 0 的邻格）翻开放。
- **后置条件**：
  - 所有被展开的格子 `isRevealed = true`。
  - 被展开的格子若原本有 `flag` 或 `question` 标记，标记必须被清除。
  - 展开不得越过地雷，不得翻开任何地雷。
  - 展开是终止的（有限棋盘，同一格不重复处理）。
- **边界**：位于棋盘角、边的格子，其邻域只包含棋盘内的格子。

### FR-06 相邻雷数计算

- **描述**：每个非雷格子的相邻雷数必须是其 8 邻域内真实地雷的数量。
- **前置条件**：已布雷。
- **行为**：对每个非雷格计算 `count`，取值范围 0–8。
- **后置条件**：格子显示的数字必须等于该 `count`。

### FR-07 首击必安全

- **描述**：本局的第一次翻开动作必须永远不踩雷，并且应尽量为玩家开出一片空白区。
- **前置条件**：游戏状态为 `ready`。
- **行为**：
  1. 记录首击坐标 `(r, c)`。
  2. 计算**安全区** = `(r, c)` 及其 8 邻域内所有在棋盘内的格子。
  3. 从安全区**之外的**格子中随机选取 `mineCount` 个作为地雷。
  4. 计算全部格子的相邻雷数。
  5. 若安全区的格子覆盖了棋盘上所有格子（即不可能在区外布雷），则退化为**唯一豁免格**策略：只保证 `(r, c)` 自身不是雷，其余格子照常布雷。
  6. 然后按 FR-04 正常执行翻开（此时 `(r, c)` 必非雷）。
- **后置条件**：
  - `(r, c)` 不是地雷。
  - 地雷总数精确等于 `mineCount`。
  - 游戏状态从 `ready` 变为 `playing`，时钟开始计时。
- **退化场景说明**：初级 9×9/10 雷、中级 16×16/40 雷、高级 16×30/99 雷在任意首击位置都满足「区外格子数 ≥ 雷数」，因此退化策略在三个内置难度下不会触发，但必须实现以保证逻辑完备。

### FR-08 右键标记循环

- **描述**：对未翻开、未标记的格子右键单击，标记必须按 `none → flag → question → none` 循环。
- **前置条件**：格子未翻开。
- **行为**：按循环顺序推进一格标记态。
- **后置条件**：
  - 格子标记态为循环中的下一个值。
  - 剩余雷数显示按 FR-10 更新。
  - 游戏状态不变（标旗不计入「已在玩」的启动条件；标旗不启动时钟）。
- **忽略规则**：
  - 对**已翻开**的格子右键必须是空操作。
  - 游戏结束时（`won` / `lost`）右键必须是空操作。
  - 在旗帜态再右键进入问号态，不得减少旗帜计数以外产生副作用。

### FR-09 问号态

- **描述**：问号态是标记循环的中间态，语义为「疑似地雷」。
- **前置条件**：格子未翻开且标记态为 `flag`。
- **行为**：右键后标记态变为 `question`。
- **后置条件**：
  - 格子显示 `?`。
  - 问号**不计入**旗帜数，因此剩余雷数显示必须相应 +1。
  - 问号不阻止 FR-04 的翻开（左键可正常翻开问号格）。
  - 问号格参与 FR-04 的翻开后，标记被清除。

### FR-10 HUD：剩余雷数

- **描述**：界面必须显示「剩余雷数 = 总雷数 − 旗帜数」。
- **前置条件**：存在游戏状态。
- **行为**：每次旗帜数量变化后重算并重绘。
- **后置条件**：
  - 显示为 3 位数字，不足补零（如 `010`、`008`、`000`）。
  - 当旗帜数超过总雷数时，显示为**负数**，格式为 `-` 加两位数字（如 `-01`、`-05`）。
  - 最小值下限钳制到 `-99`，最大值钳制到 `999`。

### FR-11 HUD：计时器

- **描述**：界面必须显示本局已用时间，单位为秒。
- **前置条件**：存在游戏状态。
- **行为**：
  - 时钟在 FR-07 布雷发生时（即首次有效翻开时）开始计时。
  - 在游戏进入 `won` 或 `lost` 时停止计时，并冻结在停止时刻的值。
  - 在 `ready` 与 `paused-restart`（重新开始前）状态下必须为 `000`。
- **后置条件**：
  - 显示为 3 位数字，不足补零，上限钳制到 `999` 并停止递增。
  - 显示值等于从开始计时到当前（或结束）时刻的**整秒**数。
  - 计时精度以 1000ms 为周期；不得因渲染频率导致累计误差（必须由「开始时间戳」推导，而非递增计数器）。

### FR-12 失败判定

- **描述**：翻开地雷时游戏立即失败。
- **前置条件**：目标格是地雷。
- **行为**：
  1. 将游戏状态置为 `lost`。
  2. 记录踩中的格子坐标。
  3. 揭示棋盘上**所有**地雷的位置。
  4. 停止时钟。
  5. 冻结全部交互（见 FR-16）。
- **后置条件**：
  - 状态为 `lost`。
  - 所有地雷格可见（已翻开态显示 💣）。
  - 踩中的那一格有唯一的红色高亮标记。
  - 界面出现明确的失败提示（如「💥 踩雷了」）。

### FR-13 胜利判定

- **描述**：当所有非地雷格子都被翻开时，游戏立即胜利。
- **前置条件**：刚完成一次翻开与展开。
- **行为**：
  1. 判定条件为 `已翻开格数 === rows × cols − mineCount`。
  2. 若满足，将游戏状态置为 `won`。
  3. 停止时钟，冻结交互。
- **后置条件**：
  - 状态为 `won`。
  - 界面出现明确的胜利提示（如「🎉 胜利！」）。
  - 胜利判定必须在**不依赖**玩家是否标旗的情况下成立（标旗是辅助功能，不是获胜条件）。
- **实现约束**：判定必须在每次翻开后执行一次，不得依赖定时器轮询。

### FR-14 难度切换

- **描述**：切换难度必须立即以新难度开始一局全新游戏。
- **前置条件**：任意（包括游戏进行中或已结束）。
- **行为**：
  1. 读取目标难度配置。
  2. 丢弃当前局的全部状态（不询问、不确认）。
  3. 重建棋盘与 HUD。
- **后置条件**：新局状态为 `ready`，时钟归零，剩余雷数等于新难度雷数。

### FR-15 重新开始

- **描述**：必须提供「重新开始」操作，以**当前难度**开启新局。
- **前置条件**：任意。
- **行为**：与 FR-14 相同的重置流程，难度保持不变。
- **后置条件**：新局状态为 `ready`，时钟归零，棋盘清空。
- **入口**：至少提供界面上的按钮；同时支持键盘 `R`（作为便利入口，不视为无障碍承诺）。

### FR-16 终局冻结

- **描述**：当状态为 `won` 或 `lost` 时，棋盘必须完全冻结。
- **前置条件**：状态为 `won` 或 `lost`。
- **行为**：忽略一切针对格子的左键与右键操作。
- **后置条件**：
  - 棋盘视觉不再变化。
  - 唯一可用的操作是「重新开始」与「切换难度」。
- **例外**：允许界面同时提供显式的「查看棋盘」类交互，但本版本不实现。

### FR-17 右键菜单抑制

- **描述**：棋盘区域内的右键操作必须被抑制浏览器默认上下文菜单。
- **前置条件**：在棋盘区域内。
- **行为**：阻止 `contextmenu` 默认行为。
- **后置条件**：右键只触发 FR-08 的标记循环。

### FR-18 状态可观测接口

- **描述**：为支撑自动化验收，应用必须在 `window.__minesweeper` 暴露一个只读契约。
- **前置条件**：应用已加载。
- **行为与后置条件**：至少提供：
  - `getSnapshot()`：返回当前状态的深拷贝快照（至少含 `status`、`rows`、`cols`、`mineCount`、`flagCount`、`elapsedSeconds`、`revealedCount`、`board` 的二维数组）。
  - `getCell(r, c)`：返回指定格的 `{ isMine, isRevealed, mark, adjacent }`。
  - `getSeed()`：返回当前局的随机种子。
  - `newGame(difficultyId, seed?)`：以指定难度与可选种子开启新局。
  - `newCustomGame(rows, cols, mines, seed?)`：以自定义参数开启新局（参数须满足 FR-21）。
  - `chord(r, c)`：对指定格执行和弦（FR-19），与双击/中键走同一条领域命令路径。
  - `restore(snapshot)`：以指定快照恢复对局（仅用于持久化验收，见 FR-20）。
- **约束**：该接口不得允许外部**直接改写**内部状态；返回值为副本。
- **理由**：章程 C7。没有它，验收测试就只能靠像素/文本猜测。

### FR-19 和弦操作（Chord）

- **描述**：对已翻开的数字格触发和弦时，若其 8 邻域内的旗帜数等于该格数字，则自动翻开邻域内所有「未翻开且未标旗」的格子；否则为空操作。
- **前置条件**：目标格已翻开、非雷、`adjacent > 0`（数字格）；游戏状态为 `playing`。
- **触发方式**（由用户确认）：
  - 桌面端：在数字格上**双击**（`dblclick`）或**中键单击**（`auxclick`，`button === 1`）。
  - 移动端：**不支持和弦**（见 FR-22）。
- **行为**：
  1. 统计目标格 8 邻域内 `mark === 'flag'` 的格子数 `f`。
  2. 若 `f !== adjacent` → 空操作（返回原状态）。
  3. 若 `f === adjacent` → 对每个「未翻开、非旗」的邻格执行翻开（含 FR-05 展开）。
  4. 若其中某格是地雷（说明玩家标错了旗）→ 执行 FR-12 失败流程，`explodedAt` 为该地雷。
  5. 翻开结算后执行 FR-13 胜利判定。
- **后置条件**：与 FR-04 / FR-12 / FR-13 一致。
- **忽略规则**：对未翻开格、空白格（`adjacent === 0`）、已终局的棋盘，和弦必须是空操作。

### FR-20 游戏进度持久化

- **描述**：进行中的对局必须完整保存到 `localStorage`，刷新或重开浏览器后自动恢复。
- **前置条件**：对局状态为 `ready` 或 `playing`。
- **保存内容**：完整 `GameState`（配置 + 棋盘 + 状态 + 种子 + 首击坐标 + 踩雷坐标 + 计时起止时间戳），外加存档版本号。
- **保存时机**：每次状态变化后立即写入（翻开 / 和弦 / 标旗 / 切难度 / 重开）。
- **终局行为**：状态变为 `won` 或 `lost` 时**删除**存档（用户确认：终局不保存）。
- **恢复行为**：应用加载时若存在合法存档且状态为 `ready`/`playing`，则恢复该对局并渲染；否则以默认难度开局。
- **计时语义**：`startedAt` 以绝对时间戳（epoch ms）持久化，因此离开页面的时间计入用时（与「游戏一直在跑」一致），上限仍为 999 秒。
- **健壮性**：存档损坏、版本不匹配、字段非法时必须静默丢弃并回退到新局，**不得**抛出未捕获异常或白屏。
- **约束**：`src/core/**` 不得引用 `localStorage`（章程 C1）；序列化/反序列化为纯函数，`localStorage` 读写封装在表现层。

### FR-21 自定义难度

- **描述**：玩家可输入宽（cols）、高（rows）、雷数（mineCount）开一局自定义难度的游戏。
- **前置条件**：点击「自定义」入口。
- **参数约束**（经典 Windows 范围，用户确认）：
  - `cols`（宽）：整数，9–30。
  - `rows`（高）：整数，9–24。
  - `mineCount`（雷）：整数，10–668，且 `mineCount ≤ (cols − 1) × (rows − 1)`。
- **行为**：
  1. 校验参数；非法时显示明确错误信息，**不**开局。
  2. 合法时构造 `config = { id: 'custom', name: '自定义', rows, cols, mineCount }`，按 FR-14 开启新局。
  3. 「自定义」按钮置为选中态。
- **后置条件**：新局棋盘尺寸与雷数与输入一致；剩余雷数显示为雷数。
- **输入体验**：数字输入框使用 `type="number"` + `inputmode="numeric"`；预填上一次的自定义值或默认 `16 × 16 × 40`。
- **首击安全保证**：约束 `mineCount ≤ (cols−1)×(rows−1)` 保证安全区外有充足格子；即使被绕过，领域层 `layMines` 的退化路径仍保证首击非雷（EC-14）。

### FR-22 移动端手势

- **描述**：触屏设备上支持「单击翻开、长按标旗」。
- **前置条件**：触屏设备（`pointerType === 'touch'`）。
- **行为**：
  1. **单击**：与左键翻开等价（FR-04）。
  2. **长按**：按住约 500ms 且位移不超过阈值（10px）时，对目标格执行标记循环（FR-08）；长按后不触发随后的合成 `click`。
  3. 长按期间手指移动超过阈值，视为滚动，取消长按。
  4. 长按不得弹出浏览器上下文菜单或触发文本选择 / 双击缩放。
- **后置条件**：与 FR-04 / FR-08 一致。
- **不支持**：触屏上**不提供**和弦操作（FR-19 仅桌面端）。
- **约束**：格子需 `touch-action: manipulation`；手势实现不得影响桌面鼠标行为。

## 7. 状态机

```
                 ┌──────────────────────────────┐
                 │                              │
   [加载/切难度/重新开始]                       │
                 │                              │
                 v                              │
             ┌───────┐   左键翻开(非雷)   ┌──────────┐
             │ ready │ ─────────────────> │ playing  │
             └───────┘   (触发布雷+计时)   └──────────┘
                 │                        │        │
                 │                        │        │ 翻开全部非雷格
                 │                        │        v
                 │                        │   ┌────────┐
                 │                        │   │  won   │ (冻结)
                 │                        │   └────────┘
                 │                        │ 翻开地雷
                 │                        v
                 │                   ┌────────┐
                 │                   │  lost  │ (冻结)
                 │                   └────────┘
                 │
                 └──► 右键标旗在 ready/playing 下均可用，不改变 status（除计数）
```

- `ready → playing`：仅由首次有效翻开触发。
- `playing → won`：FR-13。
- `playing → lost`：FR-12（含和弦触发的失败，FR-19）。
- `won` / `lost` 为**终态**，只能通过「重新开始」（FR-15）或「切换难度」（FR-14）离开。
- **不存在** `ready → lost` 的转移（首击必安全，FR-07）。
- 和弦（FR-19）只在 `playing` 下有意义：它可能翻出地雷（→ `lost`）或翻完所有安全格（→ `won`），但**不改变** `playing` 本身的中间语义。
